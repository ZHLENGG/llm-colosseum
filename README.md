# ⚔️ LLM Colosseum: Мультиагентные дебаты

Платформа для проведения интеллектуальных баталий между локальными языковыми моделями (LLM).

## 🚀 О проекте
"Колизей" позволяет задать вопрос, на который параллельно отвечают несколько LLM-агентов. Затем агенты вступают в перекрестную критику, а независимый Судья (более мощная модель) анализирует оригинальные ответы и аргументы критики, отбрасывает необоснованные придирки и выносит финальный вердикт.

**Ключевые особенности:**
- Полностью асинхронная архитектура на FastAPI.
- Параллельная генерация ответов (`asyncio.gather`).
- Умный парсинг ответов LLM и защита от "галлюцинаций" (зацикливания).
- Взвешенное судейство: Судья анализирует перекрестную критику и учитывает объективные доводы при вынесении финального вердикта.
- Красивый и живой UI на Streamlit с автообновлением.

## 🛠️ Стек технологий
*   **Backend:** Python 3.12, FastAPI, SQLAlchemy 2.0 (async), Alembic
*   **Database:** PostgreSQL (в Docker)
*   **LLM:** Ollama (локальный запуск моделей `phi3` и `mistral`)
*   **Frontend:** Streamlit
*   **Инфраструктура:** Docker, Docker Compose

## ⚙️ Как запустить (локально)

*   Убедитесь, что у вас установлены **Docker Desktop** и **Ollama**.
*   Скачайте модели в терминале: `ollama pull phi3` и `ollama pull mistral`.
*   Создайте файл `.env` на основе `.env.example`.
*   Поднимите базу данных и бэкенд в Docker: `docker compose up -d --build`.
*   Примените миграции базы данных: `alembic upgrade head`.
*   Запустите фронтенд: `streamlit run streamlit_app/app.py`.
*   Откройте в браузере [http://localhost:8501](http://localhost:8501).

## 📊 Схема базы данных
Проект использует 4 основные таблицы:
*   `battles` — сами битвы (вопрос, статус, вердикт судьи).
*   `participants` — участники (модели-агенты).
*   `responses` — ответы агентов в 1-м раунде.
*   `critiques` — перекрестная критика агентов во 2-м раунде.

## 🧠 Как это работает (Архитектура баттла)

1. **Раунд 1 (Генерация):** Вы задаете вопрос. FastAPI через `asyncio.gather` отправляет запросы всем указанным LLM параллельно. Они не ждут друг друга.
2. **Раунд 2 (Критика):** Каждая модель получает ответ оппонента и должна написать рецензию, поставив оценку от 1 до 10.
3. **Финал (Судья):** Специальный агент (Mistral) читает оригинальные ответы, учитывает аргументы из перекрестной критики, но отбрасывает необоснованные придирки (защита от галлюцинаций), после чего выносит независимый вердикт.

## 📚 Документация API

После запуска бэкенда интерактивная документация (Swagger UI) доступна по адресу: [http://localhost:8000/docs](http://localhost:8000/docs).
Вы можете прямо из браузера отправить POST-запрос на создание нового баттла и посмотреть, как работает валидация данных.
